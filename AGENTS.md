# Experiment 10 — Cross-project User Judgment Transfer

Before working on a PatchLog redesign request:

1. Read `project-context/patchlog-brief.md` for current product facts.
2. Read `project-context/functional-map.md` for design-neutral capabilities and flow.
3. If `user-context/design-learning.md` exists, read it as accumulated user-level design judgment that came from other projects.

Context and user learning are not fixed design specifications.

## Working principle

Use your own professional judgment for information architecture, interaction, visual direction, composition, typography, layout, density, implementation, and whether additional assets are useful.

The current Streamlit app is evidence of product functionality and current implementation, not a mandatory visual target. Preserve meaningful capabilities and interactions, but do not automatically preserve its existing column structure, styling, colors, component shapes, or information hierarchy.

Do not import project-specific metaphors, layouts, copy patterns, or visual devices from unrelated projects. If user-level learning is available, translate only the underlying judgment that is relevant to PatchLog.

Do not follow a predetermined design workflow or evaluation protocol merely because one could be added. Keep the environment lightweight and let the model perform the task with its own judgment.

Preserve required product capabilities unless the user explicitly asks to change them. Preserving functionality means preserving the capability and experience, not the previous presentation format.

The user's current explicit request always takes precedence.
